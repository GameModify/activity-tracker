# Activity Tracker

Локальный сервис автоматического учёта активности для Windows и сборщик для Google Chrome. Работает отдельным процессом со своей SQLite. Клиенты подключаются через HTTP API v1; исходники Time & Games для запуска не требуются.

## Запуск

Требуется Node.js 24.12 или новее. На Windows сборщик получает активное приложение, заголовок окна и время без ввода через Win32 API. На остальных системах доступен API и приём событий Chrome.

```sh
npm ci
npm run build
npm start
```

Для фонового запуска в Windows открой `Start Activity Tracker.cmd`. Повторный запуск не создаёт второй процесс. Журнал запуска находится в `data/service.log`. Сервис слушает только `127.0.0.1:3536`. Независимый запуск сайта не запускает и не останавливает этот процесс.

Переменные окружения: `TRACKER_PORT`, `TRACKER_DATA_DIR`, `TRACKER_DESKTOP=off`. Последняя отключает сбор Windows и используется в изолированных проверках API.

## Подключение клиента

При первом старте создаётся `data/credentials.json`:

- `read`: ключ клиентского подключения, чтения интервалов и управления правилами/паузой.
- `ingest`: ключ расширения для отправки событий и технической диагностики, а также чтения/изменения узкой настройки научного чата. Он не даёт доступа к истории, общим правилам или паузе сервиса.

В Time & Games открой Настройки → Автоматический учёт, укажи адрес и ключ `read`. Настрой соответствия меток категориям. Автоимпорт включается отдельно; по умолчанию завершённые интервалы ожидают проверки. Ключи и наблюдения остаются локальными и не входят в Git.

## Google Chrome

1. Выполни `npm run build`.
2. Открой `chrome://extensions`, включи режим разработчика и загрузи распакованное расширение из `dist/chrome`.
3. Открой настройки расширения, вставь ключ `ingest` и включи сбор.
4. Разреши доступ к конкретным сайтам с видео. Обнови уже открытые вкладки этих сайтов.

По клику на значок открывается окно текущей активности: активная вкладка, обнаруженные видео (включая фоновые), длительность непрерывного воспроизведения и подтверждение отправки в сервис. Это не определение конкретной серии: название берётся из вкладки. Настройки доступны отдельной кнопкой.

Если видео встроено с другого домена, окно предложит включить сбор для плеера. Кнопка разрешает только выбранный домен и подключает сборщик к открытой вкладке; адрес каждого фильма добавлять не нужно. При доступе только к выбранным сайтам для нового домена зеркала или плеера требуется новое разрешение. Кнопка «Разрешить сбор на всех сайтах» включает HTTP/HTTPS после подтверждения Chrome; индивидуальные исключения сохраняются. Неактуальные состояния исчезают через 15 секунд, а диагностические данные очищаются при закрытии Chrome. При выключенном сборе диагностические данные плееров не сохраняются.

После обновления расширение восстанавливает регистрацию сборщика для сохранённых сайтов с действующим разрешением. Это также выполняется при запуске Chrome, изменении разрешений и открытии popup. При открытии popup выполняется прямая проверка настроенной вкладки и доступных плееров через Chrome API. Сборщик подключается к уже открытым кадрам без перезагрузки видео; повторное подключение не создаёт лишних таймеров. Кнопка «Проверить и запустить сбор» повторяет эту проверку. Разрешение Chrome и включённый сбор проверяются отдельно: выданный доступ сам по себе не добавляет сайт в список отслеживаемых. Раздел «Проверка плееров» показывает домены ответивших кадров и их состояние. Ошибки регистрации и прямой проверки видны в popup; повторно выдавать уже сохранённое разрешение не требуется.

Всплывающее окно показывает воспроизведение или паузу даже при открытой вкладке, а также позицию video/audio, если она доступна. Позиция и перемотка не участвуют в измерении времени. Названия YouTube получают префикс «YouTube:», остальные берутся из заголовка вкладки. Клиент получает текущие конечные снимки интервала и завершённую запись после паузы или закрытия вкладки. Перенос в таймлайн зависит от автоимпорта или ручного принятия на стороне клиента; всплывающее окно не запускает ручные таймеры клиента.

Базовый сбор получает адрес и заголовок активной вкладки. Дополнительное разрешение позволяет наблюдать состояния HTML video/audio, включая фоновое воспроизведение. Кадры страницы учитываются совместно. Инкогнито исключено; полный доступ к истории и содержимое сообщений не собираются. Удаляются fragment, credentials и параметры URL, кроме номера диалога `sel` на vk.com.

Проверять воспроизведение нужно на используемых видеосайтах: сторонний или защищённый плеер может потребовать отдельный адаптер. Факт воспроизведения не доказывает, что человек смотрит на экран. Для Discord первая версия видит приложение; смысл разговора автоматически не определяется.

## Правила и интервалы

Правила сопоставляют приложение, заголовок, адрес, домен или тип наблюдения с произвольной меткой занятия. Сравнение без учёта регистра: совпадение или буквальное вхождение. Приоритет больше → правило сильнее. По умолчанию есть coding для Code.exe, projects для Codex.exe, video для воспроизведения. Личные правила меняются через API или интерфейс клиента и хранятся только в SQLite.

Опрос Windows выполняется раз в 5 секунд. После 90 секунд без ввода из фокусного интервала исключается период простоя. Воспроизводящееся видео учитывается независимо от ввода. Интервал закрывается при смене занятия, паузе или отсутствии сигналов более 15 секунд; разрыв не прибавляется ко времени. Chrome хранит ограниченную очередь из 200 событий и повторяет отправку после восстановления связи. Длительная недоступность может привести к пропуску данных.

Приостановка сохраняется между запусками и закрывает текущие интервалы. Изменение правил действует на новые интервалы. Определение конкретного фильма/серии, интеграция с Discord и семантическая классификация переписки в эту версию не входят.

## Активность в чатах и документах

Сбор действий включается для конкретного сайта отдельно от воспроизведения видео. В активной странице учитываются доверенные события указателя, прокрутки и ввода; сохраняется только время события. Новый диалог сбрасывает состояние. Пауза наступает через пять минут после последнего действия, переключение окна прекращает учёт сразу. Старые события Chrome без подтверждения действий не запускают учёт чатов ВК и Telegram.

Для Windows применяется пятиминутный порог простоя активного приложения. Word сообщает имя, полный путь сохранённого файла и идентификатор окна через локальный Office COM; содержимое документа не читается. Правило resource_id / within сопоставляет папку и подпапки с меткой, учитывая границы пути. Несохранённые документы и неподтверждённые окна не получают предполагаемый путь. Steam-приложения получают метку games и идентификатор папки установки; решение о связи с библиотекой принимает клиент.

Дополнительный фоновый адаптер Windows проверяет признаки голосового соединения Discord через UI Automation. Открытая страница канала не подтверждает соединение. При недоступном дереве доступности состояние unknown не создаёт голосового интервала. Адаптер не читает сообщения и не захватывает микрофон. Работа UI Automation зависит от доступности элементов конкретной версии клиента. Word и Discord проверяются отдельным процессом; зависший адаптер не блокирует опрос активного окна.

При переключении из игры её учёт продолжается до пяти минут после последней активности. Возврат раньше этого срока сохраняет непрерывный интервал; после порога начинается пауза. Другая активная программа учитывается независимо. Смена игры, ручная пауза сбора и потеря сигналов сборщика не продлевают предыдущий сеанс.

Окно расширения показывает состояние действий отдельно от плеера: отсутствие разрешения, ожидание первого действия, потерю фокуса и пятиминутный простой. Кнопка включения запрашивает доступ только к текущему сайту и сразу подключает сборщик к открытой странице. Домены vk.com и vk.ru включаются отдельно; правила URL должны соответствовать фактическому домену. Расширение сохраняет идентификатор диалога в современных путях и параметр sel в старых адресах обоих доменов, исключая остальные параметры.

Для ВК интервалы фокуса создаются только в распознанном диалоге с подходящим правилом. Для конкретного диалога используй точное совпадение очищенного URL; переход в другой чат прекращает прежний интервал. Название правила используется как подпись записи, идентичность диалога сохраняется отдельно от заголовка вкладки.

Полный экран определяется по клиентской области окна относительно монитора этого окна, включая вторичные экраны. Сам по себе полный экран не подтверждает игру. Неизвестное приложение становится игрой после явного правила app / equals / games; для него применяется тот же пятиминутный допуск переключения фокуса. Steam-игры распознаются независимо от полноэкранности.

## ChatGPT и Codex

Сборщик Chrome различает проекты ChatGPT по устойчивому ID в адресе `/g/g-p-…/c/…`.
Разговоры одного проекта сохраняют общий resource_id; в названии записи указывается проект,
а метка по умолчанию — projects. Обычные чаты получают communication и подпись
«Общаюсь с ChatGPT». Содержимое сообщений не используется для классификации.
Правило resource_id / equals позволяет назначить проекту читаемое название и отдельную метку.

Название из интерфейса и состояние диктовки доступны после включения учёта действий
для chatgpt.com в расширении. Сборщик читает ссылку текущего проекта в навигации
и доступные признаки кнопок записи. Без разрешения используются адрес вкладки,
имя проекта из URL и общий порог простоя Chrome. Имена чатов не становятся названиями обычного общения.
При недоступном или изменившемся интерфейсе используется URL; состояние диктовки не предполагается.

Windows-приложения ChatGPT.exe и Codex.exe учитываются как «Работа с Codex», projects.
Порог простоя составляет 5 минут. Активная микрофонная сессия самого приложения
подтверждает голосовой ввод и продолжает учёт без клавиатурных событий, пока окно активно.
Адаптер Core Audio перечисляет только capture-сессии и PID владельца; звук не записывается.
Микрофон другого приложения и воспроизведение аудио не подтверждают диктовку Codex.
При ошибке Core Audio остаётся обычное определение активности по вводу.

Источники: [Chrome Tabs API](https://developer.chrome.com/docs/extensions/reference/api/tabs),
[Chrome idle API](https://developer.chrome.com/docs/extensions/reference/api/idle),
[IAudioSessionManager2](https://learn.microsoft.com/en-us/windows/win32/api/audiopolicy/nn-audiopolicy-iaudiosessionmanager2),
[GetProcessId](https://learn.microsoft.com/en-us/windows/win32/api/audiopolicy/nf-audiopolicy-iaudiosessioncontrol2-getprocessid).

Контентные сборщики останавливают свой таймер и удаляют обработчики при потере контекста расширения.
Повторная установка той же версии не создаёт второй сборщик, новая версия заменяет прежний.
Наблюдения передаются через управляемый runtime.Port. Разрыв канала немедленно останавливает
таймер и снимает обработчики, синхронный отказ отправки также завершает сборщик.
При запуске фонового процесса, установке и обновлении расширение восстанавливает сборщики
в разрешённых открытых HTTP(S)-вкладках, сохраняя исключения и пропуская инкогнито и выгруженные вкладки.
Страницы не перезагружаются. При переходе со старых версий может потребоваться один раз
обновить вкладки с оставшимся прежним кодом.

Чтение активной вкладки ChatGPT может начинаться до первого действия внутри страницы,
с учётом фокуса окна и пятиминутного системного простоя. После первого действия применяется
подтверждённое время активности страницы. Предыдущий диалог не передаёт новому свои метаданные.

## Сайты, рабочие правила и диагностика

В настройках расширения видны фактические разрешения Chrome и независимые переключатели видео/действий. Выключенные сайты остаются в списке исключений. Одновременные изменения настроек записываются последовательно. ID научного чата задаётся отдельным полем; новое значение заменяет прежние точные правила для обоих доменов ВК и двух форм адреса. Правила научных документов сохраняются.

Обычные разрешённые сайты получают метку web и структурированное поле website. Проекты ChatGPT сохраняют прежнюю классификацию. Правила могут иметь scope (focus/media/voice) и необязательный project. Для YouTube доступны media_creator (путь /@handle или /channel/ID) и media_id; метаданные читаются из доступного DOM плеера, внешний API и ключ не требуются. При недоступном канале применяется общее правило видео, без предположения о цели просмотра. Приложения классифицируются по активному окну и прежнему пятиминутному порогу простоя.

Журнал диагностики в настройках хранит последние 30 сообщений локально и передаёт до 100 последних сообщений сервису. Записываются версия, домен без пути/запроса, файл, строка и текст ошибки; переписка и содержимое страниц не собираются. Чтение /v1/diagnostics защищено ключом read, запись ключом ingest. Оба варианта потери API расширения (исключение и отсутствующий chrome.runtime) останавливают таймеры/обработчики. Сборщики находятся в каталоге collectors/<версия>, а их собственная версия сборки передаётся вместе с состоянием и видна в окне расширения. Версия фонового процесса сама по себе не подтверждает актуальность кода вкладки.

Источники: [Chrome permissions](https://developer.chrome.com/docs/extensions/reference/api/permissions), [динамические content scripts](https://developer.chrome.com/docs/extensions/reference/api/scripting), [модель content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts), [каналы сообщений](https://developer.chrome.com/docs/extensions/develop/concepts/messaging).

Сигналы фоновых вкладок и неактивных окон Chrome не меняют общий канал активной вкладки. Страницы без video/audio отправляют одно состояние обнаружения, после чего проверяют появление плеера без повторной отправки пустых наблюдений. Удаление плеера передаёт одно завершающее состояние.
